# Operations console read contract: concept map (#535)

**Status:** design reference for the OSS operations console (#533). Everything under "Today" describes shipped code with file references. Everything under "Console contract" is the **target** for #535 and is not shipped until the referenced package and tests exist. The console introduces no policy, health, cost, session or decision semantics of its own; where this document names a Go function, that function is the only place the fact is computed.

Companion documents: [legacy dashboard migration map](legacy-dashboard-migration-map.md) (what the removed dashboards showed), [authentication and key scopes](authentication-and-key-scopes.md), [gateway metrics API](gateway-metrics-api.md), [object model](object-model.md).

## 1. Principles the contract encodes

1. **One Go implementation per concept.** The console's read model (`internal/console`, target) calls the projections below; it never re-derives them. Where the CLI today computes a fact inside `internal/cmd`, the computation moves to a shared package and the CLI calls it too (noted per row as *extract*).
2. **Durable facts come from the shared store the CLI reads; live facts come from the running process and are labelled by source and age.** Evidence, sessions, plan reviews and cost evidence live in one SQLite file under `TALON_DATA_DIR` (`internal/config/config.go`, `EvidenceDBPath`). The CLI reads it directly; the console does the same. The active catalog generation, reload state and metrics-collector freshness exist only inside a running `talon serve` process and are read through a runtime probe (#538); until that probe exists they are `unknown`, never assumed.
3. **Unknown is a value.** Every DTO section carries an availability block `{state: ok|stale|unavailable|unknown, as_of, source, error}`. A missing store, a failed query, an unpriced model or an unreachable process yields `unavailable`/`unknown` with the reason, not zero and not healthy.
4. **Windows and units are explicit.** UTC calendar day `[00:00, +24h)` and UTC calendar month, as `talon costs` (`internal/cmd/costs.go:140-145`) and `fleet.Project` (`internal/fleet/projection.go`) use. Currency is the active pricing table's ISO-4217 code (`pricing.DefaultCurrency` is `USD`, `internal/pricing/loader.go:51`); legacy `_eur` JSON names stay on existing endpoints, the console DTOs use `amount` plus `currency`.
5. **Bounded queries.** Every list takes `limit` with a server maximum and a cursor; ordering is deterministic and documented per endpoint. No endpoint decodes the full evidence table on refresh.
6. **Browser credential never reaches privileged routes.** The console DTO endpoints are served by the console process behind the read-only browser session (#537); they are not mounted under the data-plane admin group and have no dev-open fallback. `TALON_ADMIN_KEY` semantics are unchanged for CLI and backend.

## 3. Transport and ownership (shipped in #535: `internal/console`, `internal/console/httpapi`, `internal/fleetview`; not yet mounted)

- `internal/console` (shipped): DTO types with `contract_version: "1"` and a per-section `availability` block (`ok|empty|unavailable|unknown`, `source`, `as_of`, `error`, `note`); `console.Service` over read-only `evidence.Store` / `session.Store` connections (`OpenReadOnly`), a `FleetSource` (today `OfflineFleetSource` over `fleetview.ProjectOffline`; the runtime probe of #538 later) and a `costs.BudgetResolver` (`FleetCapsBudgets`, source `config_effective_cap_offline`). Plan reviews and the Configuration page are not in the first cut (#543, #305).
- `internal/console/httpapi` (shipped, unmounted): `Handler(svc)` is a chi router for `GET /console/v1/{overview,use-cases,use-cases/{name},sessions,sessions/{id},evidence/{id},costs,activity,system}`; each response is one DTO with `meta {contract_version, generated_at, tenant_id}` and per-section availability; errors reuse `{error, message}` with `not_found`, `invalid_request`, `internal`. It has no listener and no authentication: the console process (#536) mounts it behind the browser-session middleware (#537). It is never mounted on the data-plane server.
- CLI changes limited to structured output over the same shared functions: `talon audit list --json`, `talon audit show --json`, `talon session list --limit`, `talon monitor --json`, `talon plan pending --json`. No semantic change to existing text output.
- Shared extractions from `internal/cmd` (each one keeps the CLI as a caller): costs payload and budget status word; session detail loader; the session denial and tool-call renderers' inputs stay in `evidence.SessionSummary`.

## 4. Discrepancies found in the current code (to correct in the shared contract, not in the UI)

| # | Where | What differs | Disposition |
|---|---|---|---|
| D1 | `/v1/status`, `/v1/copaw/stats` vs `fleet` | `CountInRange`/`CountDeniedInRange` count every record class; fleet counts request-class only (which includes intercepted tool actions); `SessionSummary.requests` further splits tool actions into `tool_calls` | Both denominators are now declared: `/v1/status` carries `counts_scope: all_record_classes` and `docs/OBSERVABILITY.md` documents both scopes (#535 slice 2). ## 5. Parity and test contract (shipped in #535 where marked)

- **Seeded fixture** (shipped: `internal/cmd/console_parity_test.go`, `internal/console/service_test.go`, `internal/costs/report_test.go`, `internal/evidence/activity_test.go`). One deterministic dataset built with real models and persistence: `evidence.Store.Store` of hand-written `evidence.Evidence` records (request-class, provider sub-attempt, tool action allowed/denied with `not_dispatched`, upstream-rejected allowed action, unpriced model, PII redaction, failover chain, two tenants, two sessions one of which is client-asserted with the People Analytics shape), `session.Store` rows, plan reviews, `agent.talon.yaml` files and a gateway config in a temp `TALON_DATA_DIR`, fixed timestamps straddling a UTC day boundary. Expected values are written by hand in the test, not computed by the code under test.
- **CLI ↔ console parity** (shipped for Overview/use cases, costs, sessions and evidence: `TestConsoleParity_*`). For each page: run the cobra command with `--json` against the fixture (`talon agents --json --url ""`, `talon session show --json`, `talon costs --json --url ""`, `talon audit list --session --json`, `talon audit show --json`, `talon plan pending --json`, `talon monitor --json`) and build the console DTO from the same fixture; compare normalized semantic fields and the hand-written expectations. Mismatch fails.
- **Real binary** (shipped: `tests/e2e/console_e2e_test.go`, `make test-console-smoke`, smoke section 43, PR CI step; the console process itself is #536, so the DTOs are served in-process over the live store). The e2e tier (`tests/e2e`, real `talon` built by `TestMain`) gains: console process start against a seeded data dir, HTTP DTOs vs CLI JSON on the same store, restart of the data-plane process (facts survive, `active_generation` reappears), data-plane killed (DTO says `offline`, store facts still served), store locked/unreadable (DTO says `unavailable`, not zero).
- **Smoke.** `tests/smoke_sections/43_console_contract.sh` (shipped) wraps the e2e proof like sections 37, 38 and 41 wrap theirs. Pairing and the read-only session's refusal of `/v1/secrets` and `/v1/runs/*` belong to #537's smoke, once that boundary exists.
- **Negative cases** (from #535/#539/#541/#542): no agents; agent never used; disabled agent (`stopped`, not failure); unknown runtime; missing/stale evidence; collector unavailable; unknown pricing; invalid reload with last-known-good; policy-denied vs upstream-rejected vs provider-failed-with-fallback vs no-fallback; tampered signature (`verification.state=invalid`); missing session id (no session fabricated); cross-tenant request returns nothing from the other tenant.
